# notepadcc

原生 Windows x64 轻量文本 / 源码编辑器。内核嵌入 Scintilla + Lexilla，外壳用 Win32 API 与 C++20
直接编写，不依赖 .NET / Qt / Electron。

设计依据见 [notepadcc详细设计说明书.md](notepadcc详细设计说明书.md)（功能基线为
[Notepad++功能全景梳理.md](Notepad++功能全景梳理.md)）。

商业化设计见 [notepadcc商业化变现方案.md](notepadcc商业化变现方案.md)；v1.1 商业化前置的
授权设计见 [notepadcc许可与激活设计.md](notepadcc许可与激活设计.md)，排期见
[notepadcc-v1.1-排期与商业化落地计划.md](notepadcc-v1.1-排期与商业化落地计划.md)；
单个渠道的落地细则见 [notepadcc闲鱼售卖方案.md](notepadcc闲鱼售卖方案.md)。

## 构建

```powershell
# 1. 拉取第三方源码（Scintilla 5.6.7 + Lexilla 5.5.4，解压到 third_party/）
powershell -ExecutionPolicy Bypass -File scripts\fetch_deps.ps1

# 2. 配置与编译（MinGW）
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

MSVC（正式发布链）**必须用 Visual Studio 生成器，不要配 Ninja**：

```powershell
cmake -S . -B build-msvc -G "Visual Studio 17 2022" -A x64
cmake --build build-msvc --config Release
```

这里有一个坑值得记下来，否则会白白踩一次：MSVC 配 Ninja 时，CMake 会把 `/showIncludes`
的提示前缀写进 `build.ninja`，而中文版 MSVC 的前缀（`注意: 包含文件:`）在写入过程中编码
错乱（UTF-8 字节被当成 GBK），于是 Ninja 永远匹配不上 cl 的输出，**头文件依赖全部丢失**
——改一个 `.h` 不会触发任何重编，只有 `--clean-first` 才有效。MSBuild 用自己的 tlog 跟踪
依赖，不受界面语言影响，所以 MSVC 侧走 VS 生成器。Ninja 留给 MinGW 用，GCC 走的是
`-MD -MF` 真正的 depfile，没有这个问题。

两个工具链的产物都落在各自的 `bin/` 下，路径一致：

```
build\bin\notepadcc.exe          # MinGW-w64（7.7 MB，静态链接）
build-msvc\bin\notepadcc.exe     # MSVC（2.2 MB，/MT 静态 CRT）
```

第三方源码需要可编译访问 `www.scintilla.org`。若网络受限，把两个 zip 手动放到
`third_party/_dl/` 后重跑 `scripts\fetch_deps.ps1` 即可。

## 运行与测试

```powershell
build\bin\notepadcc_tests.exe                            # 单元测试（MinGW 产物），1717 项
build-msvc\bin\notepadcc_tests.exe                       # 单元测试（MSVC 产物），1717 项
$env:PYTHONIOENCODING='utf-8'; python tools\ui_smoke_test.py   # 界面回归 41 段，约 8 分钟
```

**这三样不要同时跑**。非便携模式下单元测试会用 `%APPDATA%\notepadcc` 下的临时目录，
界面回归脚本还会真的启动程序、硬杀进程、改配置文件、写注册表；并行跑会互相踩到对方的
临时文件，报出与代码无关的失败（实测过一次：并行跑时 MSVC 侧冒出一批 `[FAIL]`，串行跑
连跑四次都是同一批项全绿）。界面回归脚本另有 `--multi-instance` 的启动约定，见
[notepadcc详细设计说明书.md](notepadcc详细设计说明书.md) 第 9.3 节。

## 打包发行

```powershell
powershell -ExecutionPolicy Bypass -File scripts\package.ps1            # 用 MSVC 产物（正式链）
powershell -ExecutionPolicy Bypass -File scripts\package.ps1 -Toolchain mingw -NoBuild
```

产出 `dist\notepadcc-<版本>-portable-x64\` 目录与同名 zip。包里除了程序还有两样东西：
`portable` 标记文件（放在程序旁边就不再读写 `%APPDATA%`）与 `说明.txt`。解压即用，
删目录即卸载——这一条由界面回归脚本的"绿色打包"段实测：解压到一个临时目录、**不加任何开关**
直接运行、核对会话与日志都落在程序目录里，并核对 `%APPDATA%\notepadcc` 全程未被创建。

```powershell
build\bin\notepadcc.exe                     # 普通启动（配置在 %APPDATA%\notepadcc）
build\bin\notepadcc.exe -portable           # 便携模式（配置在程序目录 config\）
build\bin\notepadcc.exe ..\some\file.cpp    # 启动即打开文件
build\bin\notepadcc.exe --crash-test        # 自检开关：就绪后故意崩一次，验证崩溃处理这条路径
build\bin\notepadcc.exe --multi-instance    # 临时覆盖"单实例"设置，允许同时多开
build\bin\notepadcc_tests.exe               # 单元测试
```

`--crash-test` 是留给自检的开关，不出现在菜单里：崩溃处理这条代码路径只有真的崩一次
才验证得了，否则"写了但没生效"是不会被任何测试发现的。它会真的触发一次访问违例，
把崩溃报告、minidump 与未保存内容写进 `config\backup\crash_<时间戳>\`，然后弹提示退出。

## 几条需要遵守的约定

- **只有 `src/edit/EditView.*` 允许调用 Scintilla 消息**。其他模块一律走它的语义化方法，
  这样将来换内核或升级 Scintilla 时改动面收敛在一个文件里。
- **Scintilla 只能在 UI 线程访问**，且新窗口/DestroyWindow 之后不得再向其发送消息。
- **命令 ID 必须落在 16 位以内**（`core::MakeCmdId`，高 4 位类别 + 低 12 位序号），
  因为菜单项 ID 与 `ACCEL.cmd` 都是 `WORD`。插件命令超范围时由宿主分配菜单槽位映射。
- **写文件必须走 `io::WriteFileAtomic`**，任何直接 `fopen(...,"w")` 都可能截断用户数据。
- **宽字符 printf 用 `%ls`**，`%s` 在标准 C 语义下是窄字符串（MSVC 差异）。
| **宏录制与回放**（`Ctrl+Shift+R` 开始/停止录制、`Ctrl+Shift+P` 播放、`Ctrl+Shift+L` 重复执行）：**录的是命令流不是键鼠事件**——所以对窗口位置、焦点、DPI 变化都不敏感，跨机器回放成功率高。三种步骤：我们自己的命令（行操作、排序、大小写、注释…这些只依赖文档内容的操作）、参数全是数值的 Scintilla 消息、以及**输入的文字**（连续输入按 300 ms 空闲合并成一步，不是一字一步）。停止录制时取名即存进 `shortcuts.xml` 的 `<Macros>` 一节，**菜单"宏"里出现一条同名命令**，可以像别的命令一样绑快捷键；重复执行可选次数（1~10000）与"跳过失败步骤继续"的宽松模式，回放期间按 `Esc` 可中断，某一步失败会明确报出"第几步、第几遍"。录制期间状态栏第 4 段显示 `● REC` | 已完成 |
| **文件夹工作区**：视图菜单"打开文件夹作为工作区…"（系统选择目录对话框）→ 左侧出现目录树（目录在前、文件在后，各自按名字不区分大小写排），**双击或回车打开文件**（选中目录则是展开/收起），菜单里另有"刷新工作区/关闭工作区/打开选中的文件"。工作区目录记在 `config.xml` 的 `general.workspaceFolder`，重启自己回来；目录暂时不在（U 盘、网络盘）时当作没有工作区，配置保留。**有工作区时"在文件中查找"的目录默认取工作区根**。为避免超大目录拖死界面，目录树模型带深度（8 层）与子项数（2000）上限 | 已完成 |
| **函数列表**：视图菜单"函数列表"（可勾选，默认关）→ 左侧出现符号树，与文件夹工作区共用左栏（两个都开就各占一半）。提取器是**每语言一套规则的纯函数**：C 家族/JS/TS 靠大括号深度 + `名字(`，Python 靠缩进（`def`/`async def`/`class`），Markdown 靠井号层级，CSS 靠花括号前的选择器；其余语言如实说明"列不出符号"而不猜。点中一个符号（双击/回车/菜单"跳到选中的符号"）光标跳到那一行并交回编辑器的焦点。**解析在后台线程**、节流 300 ms（停手才解析），迟到的结果按请求号丢弃；文档变了会自动重算。大文件档不列函数，超过 4 MB 的文件直接说明"不列符号" | 已完成 |
| **打印与导出**：文件菜单"导出为 HTML…"（样式号映射成 CSS 类、`<pre>` 式表格 + 行号列、只为用到的样式写类）与"导出为 RTF…"（颜色表 + `\cf`/`\b`/`\i`，非 ASCII 走 `\uN?`）；两者的样式外观都**从控件里读**，所以导出的颜色与屏幕上一致（含用户改过的配色与逐样式号覆盖）。默认文件名与目录取当前文档旁边、同名换后缀。"打印…"（`Ctrl+P`）走系统打印对话框，**程序从不自动打印**；排版交给 Scintilla 的 `SCI_FORMATRANGE`（比"行高 × 可用高度"估算准），外层分页循环抽成纯函数并钉了"位置不前进就停手"（不然打印任务会卡死、纸一直出）；页眉页脚支持 `$(FILE_NAME)`/`$(FILE_PATH)`/`$(PAGE)`/`$(PAGES)`/`$(DATE)`，深色主题下自动用白底黑字的省墨模式 | 已完成 |
| **插件宿主**：`plugins-sdk/notepadcc_plugin.h` 是一份**纯 C、版本化**的 ABI（x64 DLL，导出 `NpccPlugin_GetInfo`/`_Init`/`_Shutdown` 三个函数；宿主与插件通过 `size`+`abiVersion` **双向校验**；跨模块内存走宿主的 `Alloc`/`Free`）。插件放在 `<配置目录>\plugins\<名字>\`，可用 `plugin.json` 声明 DLL 名、`loadOrder`、`minHostVersion`、`dependencies`；宿主按 `loadOrder` 排序、检查依赖与版本、加载并调 `Init`，插件通过宿主的 `RegisterCommand` 注册命令（自动进"插件"菜单、可绑快捷键、**可被宏录制**），还能取配置目录、读文档文本、替换选区、写日志。**每个插件单独隔离**：加载/初始化失败只记一条可读原因（缺导出函数、不是 x64、ABI 不匹配、缺依赖…）并跳过它，不影响别的插件与主程序。设置菜单有"插件管理器"：列出发现的插件与状态、可禁用/启用（写 `plugins.xml`，**重启生效**——插件已经把回调留在了宿主里，卸库等于给悬空指针开门）。仓库里带两个示例插件（一个正常、一个故意写错 ABI），既是用法示例也是自检对象 | 已完成 |
